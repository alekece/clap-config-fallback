# MSRV CI Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fail CI when the workspace does not build on the `rust-version` declared in `Cargo.toml`.

**Architecture:** One new `msrv` job in `.github/workflows/ci.yaml` runs `cargo msrv verify` with a custom locked `cargo check`. The `build` job waits on it.

**Tech Stack:** GitHub Actions, `cargo-msrv`.

**Spec:** `docs/superpowers/specs/2026-11-04-msrv-ci-design.md` (issue #12)

## Global Constraints

- Check only; no tests on the MSRV.
- Version derived from `Cargo.toml` `rust-version`; no hardcoded `1.89.0` in the workflow.
- Check command: `cargo check --workspace --all-targets --all-features --locked`.
- Existing jobs (`lint`, `deny`, `build-target`) and dependencies stay unchanged.
- The job must not fall back to the `rust-toolchain.toml` pin (1.94.1).

## Review Focus

- `rust-version` set below what a dependency needs (e.g. `1.88.0`): the job must fail.
- `rust-version` bumped later: the job must follow it without workflow edits.
- `rust-toolchain.toml` present: the check must still run on the declared version, not 1.94.1.
- Stale or missing `Cargo.lock`: `--locked` must fail rather than resolve newer versions.
- `cargo-msrv` install failing: the job fails visibly instead of passing silently.
